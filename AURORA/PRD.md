# PRD — AURORA (Zeta AI Character Chat)

## 1. 문서 개요

- 제품명: AURORA / Zeta AI Character Chat
- 문서 기준일: 2026-08-09
- 기준: 현재 저장소의 실제 구현. 런타임 데이터, 계정 정보, 대화 로그 및 비밀값은 검토 대상에서 제외했다.
- 제품 단계: 다중 캐릭터 AI 채팅의 운영 가능한 MVP + 차세대 스토리형 UI 프로토타입

## 2. 제품 정의

사용자는 취향에 맞는 AI 캐릭터를 선택해 한국어 중심의 역할극·일상 대화를 나누고, 대화방별 장기 기억을 바탕으로 맥락이 이어지는 답변을 받는다. 회원은 자신의 대화방과 응답 스타일을 여러 기기/세션에서 보존하며, 운영자는 캐릭터·프롬프트·모델·대화 로그를 관리한다.

### 해결하려는 문제

- 일반 AI 채팅은 캐릭터성, 관계의 연속성, 대화 분위기 조절이 약하다.
- 긴 역할극 대화는 앞선 사건·사용자 선호·관계 상태를 잊기 쉽다.
- 개인용 또는 소규모 서비스 운영자는 모델과 프롬프트를 코드 배포 없이 조정하기 어렵다.

### 제품 원칙

- 캐릭터별 개성과 첫 장면을 즉시 제공한다.
- 응답은 스트리밍으로 빠르게 보이고, 길이와 분위기는 사용자가 조절한다.
- 기억은 채팅방 단위로 격리한다.
- AI 제공자와 키는 브라우저가 아닌 서버에서만 다룬다.
- 인증하지 않아도 체험할 수 있으나, 영속화는 계정에 연결한다.

## 3. 목표와 성공 지표

### 제품 목표

1. 캐릭터 선택부터 첫 대화까지의 진입 마찰을 최소화한다.
2. 장기 대화에서도 캐릭터, 사용자 선호, 주요 사건의 일관성을 유지한다.
3. 운영자가 캐릭터와 프롬프트, 모델을 안전하게 조정할 수 있게 한다.
4. 모바일 브라우저에서도 앱처럼 사용할 수 있게 한다.

### 제안 KPI

| 영역 | 지표 | 초기 목표 |
| --- | --- | --- |
| 활성화 | 캐릭터 선택 후 첫 메시지 전송률 | 70% 이상 |
| 몰입 | 활성 사용자당 주간 유효 대화 턴 수 | 20턴 이상 |
| 지속성 | 7일 내 같은 대화방 재방문율 | 30% 이상 |
| 품질 | 응답 완료율(오류·취소 제외) | 98% 이상 |
| 성능 | 첫 스트리밍 토큰까지의 p95 | 제공자 환경별 별도 기준 수립 |
| 운영 | 모델/프롬프트 변경 후 설정 저장 성공률 | 99% 이상 |

현재 코드에는 관리자용 로그와 성능 로그의 기반은 있으나, 위 KPI를 집계·시각화하는 분석 대시보드는 구현되어 있지 않다.

## 4. 사용자와 권한

| 역할 | 핵심 목적 | 권한 |
| --- | --- | --- |
| 비회원 방문자 | 캐릭터 탐색 및 즉시 체험 | 캐릭터 조회, 비로그인 채팅. 브라우저 세션 식별자를 사용한다. |
| 회원 | 장기적·개인화된 대화 | 가입/로그인, 프로필 이름 변경, 자신의 대화방·메모리·응답 스타일 저장 및 관리 |
| 관리자 | 콘텐츠와 서비스 운영 | Bearer 관리자 토큰으로 캐릭터, 모델, 프롬프트, 최근 대화 로그 관리 |

## 5. 핵심 사용자 흐름

```text
홈(캐릭터 탐색)
  → 캐릭터 선택
  → 채팅방 생성 + 캐릭터 첫 장면 표시
  → 메시지 전송 / 응답 스트리밍
  → 턴·로그·기억 저장
  → 다음 대화에서 관련 기억 검색 후 컨텍스트에 반영

회원 흐름: 가입/로그인 → 기존 채팅방·응답 설정 복원 → 대화 지속
관리자 흐름: /admin 인증 → 모델/캐릭터/프롬프트 편집 또는 로그 확인 → 서버 파일에 저장
```

## 6. 기능 요구사항

### FR-01. 캐릭터 탐색과 채팅 시작

- 홈에서 활성 캐릭터의 이름, 아바타, 소개, 태그를 보여준다.
- 사용자가 캐릭터를 선택하면 해당 캐릭터를 가진 새 채팅으로 이동한다.
- 새 채팅방에는 캐릭터가 정의한 첫 장면을 첫 AI 메시지로 자동 표시한다.
- 캐릭터가 제거되거나 비활성화되어 더 이상 사용할 수 없으면 기존 목록에서 안전하게 제외한다.

**완료 기준:** 기본 캐릭터 설정이 없거나 파일을 읽지 못해도 앱 내 기본 캐릭터로 탐색과 채팅 시작이 가능하다.

### FR-02. 대화방 관리

- 사용자는 현재 캐릭터 또는 선택한 캐릭터로 새 대화방을 만든다.
- 사이드바에서 대화방 목록을 열고 대화방을 전환한다.
- 대화방은 제목, 최근 메시지/시각, 캐릭터, 메시지 목록, 아카이브 시각, 선택적 커스텀 프롬프트를 가진다.
- 사용자는 대화방을 삭제하고, 아카이브된 방을 복원할 수 있다.
- 회원의 대화방은 계정별로 저장한다. 비회원의 현재 대화는 브라우저 상태에서 동작한다.

**완료 기준:** 로그인한 사용자가 새로고침 또는 재로그인한 뒤에도 자신이 저장한 대화방을 불러올 수 있다.

### FR-03. 메시지 작성 및 제어

- 사용자는 텍스트 메시지를 전송한다.
- 사용자는 AI가 응답 중일 때 생성을 중단할 수 있다.
- 사용자는 AI에게 다음 장면을 이어 달라는 의미의 ‘턴 건너뛰기’를 요청할 수 있다.
- 사용자는 자신의 메시지를 수정하거나 삭제하고, AI 메시지를 재생성할 수 있다.
- 클라이언트는 AI 응답 토큰을 실시간으로 표시하고, 최종 완료 상태로 전환한다.

**완료 기준:** 요청 취소, 네트워크 오류, 모델 오류가 사용자에게 실패 상태로 표시되고, 기존 대화 내용은 손실되지 않는다.

### FR-04. 응답 스타일

- 사용자는 분위기를 `착한맛`(차분·안정) 또는 `매운맛`(감정·상황감 강화)으로 선택할 수 있다.
- 사용자는 `단문`(1~2문장), `중문`(2~4문장), `장문`(자세한 맥락) 길이를 선택할 수 있다.
- 선택값은 시스템 프롬프트와 제공자 토큰 예산에 반영한다.
- 회원의 응답 스타일은 계정 설정으로 저장한다.

**완료 기준:** 요청마다 스타일 값이 서버에서 정규화되고, 허용되지 않은 값은 기본 스타일로 안전하게 대체된다.

### FR-05. 캐릭터성 및 커스텀 지시

- 캐릭터는 이름, 아바타, 소개, 태그, 첫 장면, 페르소나 요약, 모델 연결 정보를 가진다.
- 사용자는 채팅방 단위로 캐릭터 지시문을 추가·수정해 해당 방의 대화 스타일을 보완할 수 있다.
- 서버는 캐릭터 페르소나, 응답 스타일, 길이 규칙, 최근 대화, 장기 기억을 조합해 모델용 메시지를 구성한다.

**완료 기준:** 커스텀 지시문은 최대 길이 제한을 적용하며 다른 대화방이나 캐릭터 설정을 변경하지 않는다.

### FR-06. 장기 기억과 관계 맥락

- 매 성공 대화 턴의 원문은 채팅방별 턴 로그에 보존한다.
- 시스템은 대화 요약, 사용자 프로필 사실, 선호, 관계 상태, 공동 사건, 관계 그래프, 대화 청크를 관리한다.
- 현재 질문이 기억 검색이 필요한 신호를 보이면 BM25 방식과 시간 감쇠를 사용해 관련 문서를 우선 검색한다.
- 검색된 기억, 최근 사건, 관계 상태는 응답 프롬프트에 제한된 크기로 주입한다.
- 기본적으로 규칙 기반 추출을 쓰며, 별도 설정 시 로컬 모델을 사용한 메모리 추출을 지원한다.
- 메모리 상태 업데이트는 대화 종료 직후가 아니라 유휴 시간 기준으로 배치 처리하고, 문서 수가 커지면 주기적으로 압축한다.

**완료 기준:** 서로 다른 `chatId`의 기억이 모델 입력에 섞이지 않으며, 기억 조회 실패·시간 초과가 발생해도 일반 채팅은 계속 응답한다.

### FR-07. 계정과 세션

- 사용자는 이름과 8자 이상 비밀번호로 가입하고 로그인한다.
- 이름은 정규화 후 중복을 허용하지 않는다.
- 비밀번호는 scrypt 해시로만 저장한다.
- 인증 성공 시 HttpOnly 기반 세션 쿠키를 발급하고, 로그아웃 시 현재 세션을 폐기한다.
- 로그인한 사용자는 표시 이름을 변경할 수 있다.

**완료 기준:** 세션 저장소에는 원문 토큰이 아닌 HMAC 해시만 저장되며, 보호 API는 유효 세션이 없으면 거부한다.

### FR-08. AI 제공자와 모델 선택

- 서버는 LM Studio, Ollama, OpenAI 호환 API, DeepSeek를 제공자로 지원한다.
- 런타임 모델 목록을 조회하고, 관리자 설정의 모델과 병합해 선택지로 제공한다.
- 캐릭터는 기본 모델을 연결하며, 요청에 모델 선택값이 있으면 이를 검증해 사용한다.
- 스트리밍 응답은 SSE로 전달한다. 비스트리밍 호환 요청에는 JSON 응답을 제공한다.
- 주 제공자/모델이 실패하면 설정된 폴백 모델로 재시도할 수 있다.

**완료 기준:** 제공자 API 키와 내부 URL은 브라우저 응답 또는 로그에 노출되지 않는다.

### FR-09. 관리자 콘솔

- 관리자는 `/admin`에서 관리자 토큰으로 인증한다.
- 캐릭터를 생성·수정·삭제하고 기본 캐릭터와 모델 연결을 저장한다.
- 모델 감지 결과를 새로고침하고, 제공자별 상태를 확인한다.
- 응답 프롬프트 섹션과 카테고리/할당을 관리한다.
- 최근 대화 로그를 세션·사용자 기준으로 탐색하고 페이지 단위로 조회한다.

**완료 기준:** 관리자 API는 Bearer 토큰 검증 없이 데이터에 접근하거나 변경할 수 없다.

### FR-10. UI, 테마 및 PWA

- 데스크톱과 모바일에서 채팅, 대화방 목록, 헤더, 입력창을 사용 가능하게 한다.
- 사용자는 로컬 저장소에 유지되는 테마를 선택할 수 있다. 현재 테마 정의는 7종이다.
- `/pwa`에서 설치 상태, Android/데스크톱 설치 프롬프트, iOS 수동 설치 안내를 제공한다.
- 서비스 워커는 앱 셸과 정적 자산을 캐시하고, API 응답은 캐시하지 않는다.

**완료 기준:** 네트워크가 끊긴 상황에서도 이전에 캐시된 앱 셸은 열릴 수 있지만, 새 AI 응답 생성은 온라인 연결이 필요함을 명확히 한다.

## 7. 비기능 요구사항

| 분류 | 요구사항 |
| --- | --- |
| 성능 | 스트리밍을 기본값으로 사용한다. 메모리 컨텍스트 대기 시간은 환경 변수로 상한을 둔다. |
| 안정성 | 파일 저장은 잠금·임시 파일·rename 기반의 원자적 쓰기를 사용한다. 메모리 처리 오류는 채팅 본문 응답을 막지 않는다. |
| 보안 | 비밀번호·세션 토큰·관리자 토큰·제공자 키는 원문으로 로그/소스에 저장하지 않는다. 제공자 호출은 서버에서만 수행한다. |
| 남용 방지 | IP 기준 인메모리 속도 제한을 적용한다. 기본값상 채팅은 분당 30회, 모델 조회·관리 API는 분당 60회, 로그인은 5분 8회, 가입은 10분 5회다. |
| 데이터 격리 | 계정 데이터는 사용자 ID 단위, 장기 기억은 chat ID 단위로 분리한다. |
| 운영 | Next.js 서버는 리버스 프록시 뒤에서 운영하며, 런타임 데이터는 배포 소스와 분리해 백업한다. |
| 접근성 | 버튼과 주요 아이콘에는 이름을 제공하고, 모바일 터치 사용성을 유지한다. 정식 접근성 검증은 별도 필요하다. |

## 8. 데이터와 API 경계

### 데이터 모델

| 데이터 | 저장 방식 | 소유 범위 |
| --- | --- | --- |
| 사용자·세션 | JSON | 계정 |
| 채팅방·응답 스타일·간단 메모리 | JSON/JSONL | 계정 |
| 전체 대화 로그 | JSONL | 운영자 조회용 |
| 턴, 요약, 관계, 검색 문서 | JSON/JSONL | 채팅방 |
| 캐릭터·모델·프롬프트·제공자 설정 | JSON/텍스트 | 서비스 전역 |

### 주요 API

| API | 목적 | 접근 |
| --- | --- | --- |
| `POST /api/chat` | 대화 생성, SSE 또는 JSON 응답 | 공개 + 속도 제한 |
| `GET /api/chatbots`, `GET /api/models` | 캐릭터/모델 선택지 | 공개 |
| `/api/auth/*` | 가입, 로그인, 로그아웃, 세션 확인 | 공개 |
| `/api/account/profile`, `/response`, `/rooms` | 내 계정·응답 설정·대화방 | 세션 필요 |
| `/api/admin/chatbots`, `/chats`, `/prompts` | 운영 콘텐츠 및 로그 | 관리자 토큰 필요 |

## 9. 현재 범위 밖 또는 미완성 항목

다음은 저장소에 화면/샘플은 있으나 실제 제품 기능으로 연결되어 있지 않으므로 MVP 완료 범위에 포함하지 않는다.

- `/profile`: 3개의 하드코딩된 프로필을 선택하는 데모다. 상세 설명과 편집 버튼은 동작하지 않으며 계정 프로필과 연결되지 않는다.
- `/chat-v2`: 하드코딩된 메시지, 장면 정보, 이미지 카드로 구성된 시각적 프로토타입이다. 입력창, 실제 AI 호출, 저장, 모델 연결이 없다.
- 이미지 카드: 샘플 외에 이미지 생성·업로드 API나 실제 저장소가 없다.
- 다인 캐릭터/장면 메타데이터: V2의 표현 모델은 있지만 실제 채팅 파이프라인과 연결되지 않았다.
- 분석·KPI 대시보드, 콘텐츠 신고·모더레이션, 비밀번호 재설정, 이메일/소셜 로그인, 다중 기기 세션 관리 UI는 없다.

## 10. 권장 다음 릴리스: 스토리 채팅 V2 제품화

### 문제

V2는 다인 캐릭터, 서술/대사 구분, 장면·이미지 카드로 더 몰입적인 스토리 경험을 제안하지만, 현재 운영 채팅의 실제 데이터·AI·기억·계정과 분리되어 있다.

### 범위

1. 기존 `ChatRoom`에 스토리 피드 아이템(메시지, 이미지, 장면 정보)을 추가하고 기존 메시지와 하위 호환한다.
2. 프로필 선택을 실제 계정의 표시 이름/아바타/대명사 설정으로 통합한다.
3. 실제 `/api/chat` 응답을 V2 렌더러에 연결하고, 다인 캐릭터 발화자 식별 규약을 정의한다.
4. 장면 날짜·시간·장소를 기억 상태에서 읽고 쓸 수 있도록 데이터 계약을 추가한다.
5. 이미지 생성은 제공자, 비용/대기 UX, 안전성, 저장 정책을 확정한 뒤 별도 API로 도입한다.

### V2 수용 기준

- 기존 계정의 채팅방을 손실 없이 V2 화면에서 열 수 있다.
- 새 메시지 전송, 스트리밍, 중단, 재생성, 기억 검색이 V2에서도 동작한다.
- 다인 캐릭터 발화는 발화자 이름·아바타·색상으로 일관되게 표시된다.
- 이미지 생성은 요청·대기·성공·실패·재시도 상태를 모두 표시하고, 생성 결과가 해당 대화방에 영속화된다.

## 11. 결정이 필요한 항목

1. 서비스의 주된 대상은 개인 비공개 사용자인가, 공개 커뮤니티 서비스인가? 공개 서비스라면 연령 정책·신고·모더레이션이 필수다.
2. 비회원 대화를 얼마나 오래 보존할지와, 회원 가입 시 이전 대화를 계정으로 이전할지 결정이 필요하다.
3. 파일 기반 저장을 계속 사용할 최대 사용자/대화량 기준과 DB 전환 시점을 정해야 한다.
4. 관리자 로그에 포함되는 대화 원문에 대한 보관 기간, 열람 권한, 삭제 요청 정책이 필요하다.
5. V2의 이미지 생성 제공자, 비용 한도, 저작권·안전성·보관 정책을 확정해야 한다.
